# Фриланс-бот с подпиской и оплатой через ЮKassa

## Что делает бот

- Пользователь запускает бота → получает **3 дня бесплатного пробного периода**.
- Пользователь с активной подпиской выбирает **категории заказов**.
- Админ через `/admin` открывает **встроенную админ-панель**:
  - создаёт/удаляет категории;
  - добавляет заявку → выбирает категорию → пишет текст → нажимает «Отправить» — заявка **мгновенно уходит всем подписчикам этой категории**;
  - смотрит статистику (пользователи, активные подписки, оплаты).
- Оплата подписки — через **прямой REST API ЮKassa**. Тарифы: неделя 290₽, месяц 450₽, 3 месяца 1000₽. Бот создаёт платёж, показывает ссылку на страницу оплаты ЮKassa (там доступны все включённые в кабинете способы — карты, СБП и т.д.), и сам, без вебхука и SSL-сертификата, каждые 15 секунд проверяет статус платежа и автоматически активирует подписку, как только оплата прошла.
- Все пользовательские экраны — это **фото + подпись + клавиатура одним сообщением** (не текст и картинка раздельно). Используются два баннера: `banner_main.jpg` — на всех экранах, `banner_categories.jpg` — только на экране выбора категорий.

## Быстрый запуск через Docker (рекомендуется)

Не нужно вручную ставить Python, PostgreSQL и зависимости — всё поднимается одной командой в изолированных контейнерах: сам бот и база данных.

### Что нужно заранее

- Установленный **Docker Desktop** (macOS/Windows) или **Docker Engine + docker compose plugin** (Linux) — [docs.docker.com/get-docker](https://docs.docker.com/get-docker/).
- Токен бота от @BotFather и данные магазина ЮKassa (см. разделы 3 и 4 ниже — они нужны в любом случае, с Docker или без).

### Шаги

1. Скопируйте `.env.example` в `.env`:
   ```bash
   cp .env.example .env
   ```
2. Заполните `.env`: `BOT_TOKEN`, `ADMIN_IDS`, `YOOKASSA_SHOP_ID`, `YOOKASSA_SECRET_KEY`, а также `POSTGRES_USER` / `POSTGRES_PASSWORD` / `POSTGRES_DB` (это создаст базу с такими данными) и `DATABASE_URL` — **хост должен быть `db`**, а не `localhost` (так называется сервис базы данных внутри docker-compose, они видят друг друга по этому имени):
   ```
   DATABASE_URL=postgresql://bot_user:ваш_пароль@db:5432/freelance_bot
   ```
3. Замените заглушки в `assets/banner_main.jpg` и `assets/banner_categories.jpg` на свои картинки (по желанию — можно и потом).
4. Запустите:
   ```bash
   docker compose up -d --build
   ```
   Это соберёт образ бота, поднимет контейнер с PostgreSQL, дождётся его готовности (healthcheck) и запустит бота — таблицы в базе бот создаст сам при старте.

### Полезные команды

```bash
docker compose logs -f bot        # смотреть логи бота в реальном времени
docker compose restart bot        # перезапустить бота после изменения кода
docker compose down                # остановить всё
docker compose down -v             # остановить и удалить данные базы (осторожно — это сотрёт всех пользователей и заявки)
docker compose up -d --build       # пересобрать и перезапустить после правок в коде
```

Данные PostgreSQL хранятся в Docker-томе `pgdata` и переживают перезапуски/пересборки — исчезают только при `docker compose down -v`.

## Запуск вручную (без Docker)

Если не хотите использовать Docker — тот же самый бот запускается и напрямую, шаги ниже.

## 1. Установка

```bash
python3 -m venv venv
source venv/bin/activate        # Windows: venv\Scripts\activate
pip install -r requirements.txt
```

## 2. Установка и настройка PostgreSQL

Если PostgreSQL ещё не установлен:

**macOS (через Homebrew):**
```bash
brew install postgresql@16
brew services start postgresql@16
```

**Ubuntu/Debian:**
```bash
sudo apt update
sudo apt install postgresql postgresql-contrib
sudo systemctl start postgresql
```

**Windows:** скачайте установщик с [postgresql.org/download](https://www.postgresql.org/download/windows/) и пройдите мастер установки (запомните пароль, который зададите для пользователя `postgres`).

Также можно не ставить PostgreSQL локально, а использовать облачную базу (например, Supabase, Railway, Timeweb Cloud, Amazon RDS) — тогда просто возьмите готовую строку подключения оттуда и пропустите шаги ниже.

**Создайте базу данных и пользователя** (пример для локальной установки):

```bash
psql -U postgres
```

В открывшейся консоли psql:
```sql
CREATE DATABASE freelance_bot;
CREATE USER bot_user WITH PASSWORD 'ваш_надёжный_пароль';
GRANT ALL PRIVILEGES ON DATABASE freelance_bot TO bot_user;
\q
```

Таблицы создавать вручную не нужно — бот сам создаст их при первом запуске (см. `SCHEMA` в `database.py`).

## 3. Создание Telegram-бота

1. Напишите **@BotFather** в Telegram → `/newbot` → задайте имя и username.
2. Получите **токен бота** (вида `123456:AAAA...`).
3. Узнайте свой Telegram ID через **@userinfobot** — он понадобится для доступа к админ-панели.

## 4. Подключение оплаты (прямой REST API ЮKassa)

Бот создаёт платёж через API ЮKassa и показывает пользователю ссылку на отдельную страницу оплаты — там доступны все способы, включённые в вашем магазине (карты, СБП и т.д.).

### Тестовый режим (для проверки, без реального магазина)

1. Зайдите в личный кабинет **yookassa.ru**, включите **тестовый режим** (переключатель обычно в правом верхнем углу).
2. В тестовом режиме зайдите в **Настройки → API** (или **Интеграция → Ключи API**) — там будут тестовые `shopId` и секретный ключ.
3. Тестовая карта для проверки: номер `5555 5555 5555 4444`, любой срок в будущем, CVC `123`.

### Боевой режим (реальные платежи)

1. Зарегистрируйте магазин на **yookassa.ru** (нужно ИП, самозанятость или юр. лицо), подпишите договор и дождитесь одобрения (обычно 1–3 рабочих дня).
2. В личном кабинете включите нужные способы оплаты (**Настройки → Способы оплаты**) — как минимум «Банковские карты». Каждый способ проверяется отдельно, включение договора в целом не гарантирует, что конкретный метод сразу заработает — если после подключения увидите ошибку вида «Вы не можете принимать платежи с карт», значит именно этот способ ещё не одобрен, пишите менеджеру.
3. Скопируйте `shopId` из **Настройки → Магазин** и секретный ключ из **Интеграция → Ключи API**.

**Важно про СБП:** если хотите принимать оплату через СБП (QR-код) — это тоже отдельно подключаемый способ, не включённый по умолчанию, и его нужно запрашивать через менеджера/поддержку ЮKassa. Именно эта схема (прямой REST API с собственной страницей оплаты) поддерживает СБП — в отличие от нативных счетов Telegram (`sendInvoice` через provider_token), где, по подтверждению поддержки ЮKassa, доступна оплата только картами, SberPay и ЮMoney, СБП там не появится ни при каких настройках.

## 5. Настройка .env

Скопируйте `.env.example` в `.env` и заполните:

```
BOT_TOKEN=токен_от_BotFather
ADMIN_IDS=ваш_telegram_id,ещё_один_id_если_нужно
YOOKASSA_SHOP_ID=shopId_из_кабинета
YOOKASSA_SECRET_KEY=секретный_ключ_из_кабинета
DATABASE_URL=postgresql://bot_user:ваш_надёжный_пароль@localhost:5432/freelance_bot
```

## 5.1 Замена баннеров на свои

В папке `assets/` лежат два файла-заглушки, сгенерированные автоматически (просто цветной фон с надписью) — их нужно заменить своими картинками:

- `assets/banner_main.jpg` — показывается на всех экранах бота (главное меню, подписка, оплата).
- `assets/banner_categories.jpg` — показывается только на экране выбора категорий.

Просто положите свои файлы с теми же именами в `assets/`, заменив заглушки. Рекомендации:
- Одинаковый размер у обоих баннеров (например, **1280×640**), чтобы экраны визуально не "прыгали" при переключении.
- Формат JPG или PNG.
- Подпись под фото (текст сообщения) ограничена Telegram **1024 символами** — если у вас появится более длинный текст на каком-то экране, отправить его как подпись к фото не получится.

Если хотите использовать другие имена файлов или расположить их не в `assets/`, а где-то ещё — путь настраивается через `BANNER_MAIN` и `BANNER_CATEGORIES` в `.env` (необязательно, по умолчанию берутся файлы из `assets/`).

## 6. Запуск

```bash
python main.py
```

При первом запуске бот сам подключится к PostgreSQL и создаст все нужные таблицы (если их ещё нет).

## 7. Первые шаги после запуска

1. Напишите боту `/start` от имени администратора — вам активируется пробный период, а в главном меню появится кнопка «🛠 Админ-панель» (по вашему ID из `ADMIN_IDS`).
2. Зайдите в «Админ-панель» → «Категории» → добавьте несколько категорий (например: «Дизайн», «Разработка сайтов», «Копирайтинг»).
3. Дайте ссылку на бота реальным пользователям — они запускают `/start`, получают пробный период, заходят в «Мои категории» и отмечают нужные.
4. Когда у вас появляется новый заказ — «Админ-панель» → «Добавить заявку» → выбираете категорию → вставляете текст заявки → «Отправить подписчикам». Заявка мгновенно уходит всем, у кого выбрана эта категория и активна подписка/пробный период.

## 8. Как работает продление подписки

- Оплата продлевает подписку **от текущей даты окончания**, если она ещё не истекла (т.е. подписки суммируются, а не перезаписываются), либо от текущего момента, если подписка уже закончилась.
- Пробный период и платная подписка используют одно и то же поле `sub_until` — с точки зрения доступа к категориям разницы нет.
